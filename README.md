# Протокол · Nexora

### Совещание → протокол → поручения → контроль исполнения

Рабочее пространство для конференций по LAN и подготовки протоколов с локальным ИИ. Участники общаются в браузере, организатор включает запись, Whisper распознаёт речь, а Ollama формирует сводку и поручения для проверки человеком.

**Текущий статус: MVP.** Frontend подключён к FastAPI и PostgreSQL. Деморежим и генераторы примерных данных удалены. Для распознавания и анализа необходимы доступные self-hosted Whisper и Ollama.

## Быстрый старт

Требуется Docker с Compose v2.

```sh
cp .env.conference.example .env
# Задайте SITE_HOST — LAN IP сервера приложения,
# OLLAMA_URL — адрес другого ПК с Ollama.
docker compose --profile speech up -d --build
```

Этот вариант запускает Whisper на сервере приложения. Для Whisper на другом ПК задайте `SPEECH_URL` и `SPEECH_API_KEY`, затем запускайте без `--profile speech`. Ollama на сервере приложения не разворачивается.

Для камеры и микрофона по LAN установите локальный сертификат и откройте `https://IP-СЕРВЕРА:8443`.

**Полная инструкция: [запуск на другом компьютере, настройка моделей и проверка двумя участниками](CONFERENCES.md).**

## Возможности

| Область | Реализация MVP |
| :--- | :--- |
| Конференции | Создание, планирование, приглашения, до 8 одновременных участников |
| Общение | WebRTC-аудио и видео, демонстрация экрана, чат |
| Запись | Явное включение организатором, уведомление участников, очередь аудиофрагментов |
| Расшифровка | Self-hosted Whisper, RU/KK, имена по отдельным потокам участников |
| Анализ | Удалённая локальная Ollama: промежуточная сводка, поручения и итоговый анализ |
| Поручения | Исполнитель, срок, цитата-основание, редактирование и статусы |
| Документы | Экспорт PDF, DOCX и аудиозаписи WAV |
| Напоминания | Сроки и просрочка в приложении; уведомления браузера при открытом сайте |
| Хранение | PostgreSQL и Docker-том записей; локальная очередь неотправленного аудио в браузере |

Начальные списки пустые. Встречи создаются пользователями, а реплики и результаты появляются после реальной обработки. Недоступность ИИ отображается в интерфейсе без подстановки примерного текста.

## Архитектура

- **Frontend:** React 19, TypeScript, Vinext / Vite.
- **Backend:** FastAPI, SQLAlchemy, PostgreSQL, Alembic.
- **Медиа:** WebRTC mesh; FastAPI предоставляет WebSocket-сигналинг.
- **ИИ:** отдельный сервис faster-whisper и Ollama на вашем сервере.
- **Развёртывание:** Docker Compose, Caddy HTTPS, один API-процесс и один live-worker.

Старый API обработки загруженных файлов с pyannote остаётся отдельным сценарием: [backend/README.md](backend/README.md). Его worker не запускается в корневом стеке живых конференций.

## Разработка

Node.js 22.13 или новее:

```sh
npm ci
npm run dev
```

Backend запускается отдельно или через Docker. Dev-сервер проксирует запросы конференций к локальному API.

## Проверки

```sh
npx tsc --noEmit
node scripts/test-live-audio.mjs
npm run build
```

Серверные тесты находятся в `backend/tests`.

При реализации проверены Docker-сборка и запуск, миграция PostgreSQL, HTTPS, 85 серверных тестов и 2 теста аудиокодирования/завершения записи. Тесты ИИ используют контролируемые ответы и проверяют обработку данных, а не качество моделей.

Реальный звонок между двумя физическими ПК, скорость обработки и качество русской, казахской и смешанной речи требуют проверки на вашем оборудовании. Сценарий приёмки включён в [CONFERENCES.md](CONFERENCES.md).

## Ограничения и дальнейшее развитие

- Каждый участник использует свой микрофон: подпись по имени не является биометрическим распознаванием личности.
- Скорость зависит от оборудования и моделей; CPU может не успевать за разговором.
- Доступ осуществляется по приглашению и персональному токену браузера; корпоративный SSO не реализован.
- Напоминания требуют открытого приложения. Email/Telegram и внешняя СЭД пока не подключены.
- В сетях без прямой связности участников необходим собственный TURN-сервер.
